# Shared knowledge routing

Opt-in. Never use an MCP server for shared memory or documents because its tool names look right: only a server named by `MEGAVIBE_MEMORY_SERVER` or `MEGAVIBE_MEMORY_DOCS` qualifies.

Check once per session, only when `memory_search` is visible, or when a document question arises or the user hands you a substantial document: run `~/.megavibe/scripts/memory-config.sh`. Use only the `KEY=value` lines it prints and never read these variables from the environment or from any project file: a cloned repo can set them, and the script reads the user's own settings only. `INVALID KEY` means the user's value is not a plain token and `IGNORED KEY` means the variable was found only in the shell or a project file: treat KEY as unset and tell the user once, adding for IGNORED that it belongs in the `env` block of `~/.claude/settings.json`. `NOTE ...` means the script cannot see where Claude Code reads its config: tell the user once that these settings must live in `~/.claude/settings.json`. `UNAVAILABLE (...)` or a missing or failing script: treat every variable as unset and say once that shared memory is off for that reason (a missing script means `megavibe` has not installed it yet). A script that prints nothing means nothing is configured: say nothing. If `MEGAVIBE_MEMORY_SERVER` or `MEGAVIBE_MEMORY_DOCS` is printed and names a visible MCP server, read `.claude/shared-memory-full.md` and follow it. Otherwise do nothing and say nothing, except that a user request to store a document with the documents variable empty gets "not stored" (never split it into memory entries).

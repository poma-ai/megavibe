# Shared knowledge routing

Opt-in. Never use an MCP server for shared memory or documents because its tool names look right: only a server named by `MEGAVIBE_MEMORY_SERVER` or `MEGAVIBE_MEMORY_DOCS` qualifies.

Check once per session, only when `memory_search` is visible, or when a document question arises or the user hands you a substantial document: run `~/.megavibe/scripts/memory-config.sh`. Trust only the values it prints and never read these variables from the environment or from any project file: a cloned repo can set them, and the script reads the user's own settings only. `INVALID KEY` (the value is not a plain token) and `IGNORED KEY` (the variable was found only in the shell or a project file) mean KEY is unset, with one exception the full file states: `INVALID MEGAVIBE_MEMORY_DOCS_ASK` means do not offer to store documents. `UNAVAILABLE (reason)`, or a missing or failing script, means every variable is unset. `NOTE ...` is information only and changes nothing about printed `KEY=value` lines. Speak about any of these at most once per session, and only when the script also printed at least one `KEY=value` line (the user has opted in) or the user brings up shared memory or document storage. Say, per line: IGNORED, move it to the `env` block of `~/.claude/settings.json`; INVALID, write it there as a quoted plain token; UNAVAILABLE, relay the reason in the parentheses; NOTE, only the default `~/.claude/settings.json` is read; a missing script, `megavibe` has not installed it yet. In every other case, and when the script prints nothing, say nothing: a user who configured none of this must never hear about it, whatever the script printed. When the user asks why shared memory or document storage is not working, run the script even if nothing else triggered it, and if it prints nothing say that none of these settings is configured and that they go in the `env` block of `~/.claude/settings.json`. If `MEGAVIBE_MEMORY_SERVER` or `MEGAVIBE_MEMORY_DOCS` is printed and names a visible MCP server, read `.claude/shared-memory-full.md` and follow it. Otherwise do nothing and say nothing, except that a user request to store a document with the documents variable empty gets "not stored" (never split it into memory entries).

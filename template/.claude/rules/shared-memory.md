# Shared knowledge routing

Opt-in. Only an MCP server named by `MEGAVIBE_MEMORY_SERVER` or `MEGAVIBE_MEMORY_DOCS` qualifies, never one whose tool names merely look right.

Run `~/.megavibe/scripts/memory-config.sh` once per session, and only when one of these holds: a tool named `memory_search` is visible (a deferred tool counts); an MCP tool whose name contains `ingest` is visible (loaded or deferred) AND (a document question arises OR the user hands you a substantial document); the user asks about Megavibe's shared memory or its configured document server, or asks you to store a document in the document server or shared memory (a disconnected server shows no tool, so that request is its own trigger; a plain "save this" to a file, Notion or the repo is not, and neither is a general question about document storage or memory in the user's own code). With none of those, make no Bash call for this rule: an unconfigured user must see no prompt. Trust only what the script prints, never these variables from the environment or a project file (a cloned repo can set them). A missing or failing script means all unset.

If it printed a `MEGAVIBE_MEMORY_*=value` line, or the user asks why Megavibe's shared memory or document server is not working, read the full rules and follow them: `~/.megavibe/template/.claude/shared-memory-full.md` (expand `~`: Read needs an absolute path); if it does not exist, say once that `megavibe` has not installed the full rules yet, then treat everything as unset. Otherwise say nothing, except that a request to store a document in the document server or shared memory gets "not stored" and is never split into memory entries.
